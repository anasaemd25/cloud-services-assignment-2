Question 1: Compare application containers to microservices

Microservices and application containers are two different concepts that work together. Microservices are an architectural software design where an application is broken down into small independent pieces, and each of those perform a specific task (for example a login or payment service etc...).
Application containers are a packaging and deployment technology that packs code, dependencies, and runtimes into very lightweight units. While microservices can run inside containers, they are not the same thing: microservices are how you design software , and containers are how you package and run software .

Question 2: What is Kubernetes and what alternatives are there?

Kubernetes is an open-source container orchestration platform used to automate the deployment, scaling and managin containerized applications across multiple servers. Running a single container manually is kinda simple, but managing hundreds requires an automated orchestrator like Kubernetes to handle tasks like self-healing and auto-scaling.
Popular alternatives include Red Hat OpenShift (used by CSC Rahti), Docker Swarm , HashiCorp Nomad , and Apache Mesos .

Question 3: Virtualization platform for a Windows VM on a laptop

If I needed to run a virtualized Windows operating system on my laptop, I would choose VirtualBox or VMware Workstation . I have used both for over five years, including setting up specialized Linux distributions like Kali and Parrot OS, both offer reliable virtualization. VirtualBox is very good because it is completely free, open-source, beginner-friendly, and cross-platform. Alternatively, VMware provides excellent performance and hardware acceleration for resource-heavy operating systems like Windows or Windows Server.

Question 4: Security risks when using third-party containers

When using third-party containers, key security risks include:
  • Vulnerabilities in Outdated Base Images: Images often contain unpatched operating system packages or dependencies with known security flaws (CVEs), as well as vulnerabilities susceptible to zero-day attacks and malware.
  • Malicious Images: Public repositories can host images containing hidden malware, crypto-miners, or backdoors.
  • Over-Privileged Execution: Containers defaulting to root user permissions can lead to container escape attacks if compromised.
  • Exposed Secrets: Hardcoded passwords, API keys, or private SSH keys left in image layers can be extracted by users with bad intentions.
